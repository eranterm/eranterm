Getting started

  1. Click ＋ New connection on the Home page.
  2. Choose the type (SSH or RDP), then enter the host, port, and login: a username with a password or private key, or a saved User.
  3. Optionally set a group, tags, details, and mark it as a favorite. Then click Save.
  4. Click ▶ SSH on the server. Each connection opens in its own tab at the top of the window, on the module chosen in Settings (File Manager by default). ⌂ Home always takes you back. Drag tabs to reorder them. If a connection fails or drops, ⟳ Reconnect failed appears at the right of the tab row and reconnects all of them in place. A server's group is shown above its name at the top of its page.

The + at the right of the tab row opens a localhost tab: a terminal on this computer (your login shell), with terminal sessions, scripts and AI like any server. It has no File Manager, Logs or Metrics. Available on macOS and Linux.

The first time you connect, EranTerm remembers the server's host key. If that key changes later, EranTerm accepts the new one and warns you, so you can check it was expected (for example after a reinstall).

Home: servers & groups

  • Search filters by name, IP, user, or tag.
  • All Servers, Favorites, and each group in the side menu filter the table. Click a column header to sort.
  • Groups: click ＋ next to Groups to create one, or type a new group name when you edit a server. You can rename or delete a group from its row; deleting a group keeps its servers.
  • Group colors: in the group's Edit dialog, pick a soft color (or none). It tints the group's row on Home, its entry in the side menu, and the tabs of that group's servers.
  • The State column shows whether the server answers: green = available, red = not available, grey = not checked yet. Hover the dot for the date and time of the last check.
  • The ▶ SSH and 🖥 Desktop buttons (RDP, VNC or Screen Sharing) each show a dot for their own protocol: green when its port answers, red when it doesn't. Hover for the time of the check.
  • Checks run in the background and never slow down the app or your connections: one quick TCP connection per port, 2 s timeout, every minute by default. Change the interval or turn checking off in Settings → Server Availability; turn it off for one server with Check availability in its Edit dialog.
  • When a server goes down or comes back up, you get a desktop notification (see Settings → Notifications).
  • The Alerts column shows servers that are over a CPU, memory, or disk limit you set (see Metrics).
  • ‹ folds the side menu down to icons.

Users (saved logins)

Save a username with a password and/or private key once, then pick it under Login for any number of servers. When you change the saved user, every server that uses it gets the change.

Windows & RDP

  • Desktop opens Remote Desktop: Windows App on macOS (from the Mac App Store), or mstsc on Windows. A saved password is copied to the clipboard for the login prompt and cleared after 45 seconds.
  • ▶ SSH uses Windows OpenSSH with the same login (DOMAIN\user when you set a domain), so you also get the terminal, files, logs (from PowerShell), and metrics.

File Manager

  • Browse folders, type a path and press Enter, or use Home folder and Parent folder.
  • Upload: drag files or folders from your desktop into the window. Download: use the row action. Folders are transferred as .tar.gz.
  • Transfers show their progress at the bottom of the window. Columns sort when you click their header.
  • Open any folder in a side terminal or in the main terminal, copy a file's path, or Add to Logs to tail a file.

Terminal & scripts

  • A full shell. You can open several sessions per server.
  • As you type, command suggestions come from this server's history and from common commands.
  • Scripts: a searchable library of commands and multi-line scripts, with tags. Click one to run it in the terminal. Scripts can use variables; manage them all in Scripts on the Home page. You can import and export scripts (.json, .sh, .txt), and re-add any built-in scripts you deleted. Tick Run as root on a script to run it with sudo (marked 🔒); sudo asks for the password in the terminal unless the user has passwordless sudo. Tick Wait for Enter (marked ⏎) to have Run type the script into the terminal without executing it; press Enter to run it. Hide built-in scripts shows only the scripts you added; the choice is remembered.

Writing scripts

Manage scripts in Scripts on the Home page (or { } Scripts in any terminal). Run them from a server Terminal or from Broadcast.

One line or many

  • A one-line script is typed into the terminal as is, followed by Enter: df -h.
  • A multi-line script runs as one script through sh, so loops, if blocks and functions work. Start it with a #! line to pick another interpreter, for example #!/bin/bash or #!/usr/bin/env python3.
  • Run as root runs it with sudo. Wait for Enter types it without running it, so you can check it first.

Ask AI

  • At the top of the New / Edit script form, describe what the script should do (or what to change in the current one) and click ✦ Ask AI or press Enter.
  • The AI returns a proposal: a short plan, the script, suggested local variables and a risk level. Nothing changes until you click Apply to form.
  • Apply replaces the script text, adds the suggested local variables, sets Run as root, and fills Name, Description and Tags only if they are empty. Review it before saving.
  • Your request, the current name, description and script, and the names of your variables are sent to the AI provider set in Settings → AI configuration. Variable values are not sent.

Variables

Write {{name}} anywhere in a script. When you click Run, EranTerm replaces it with the variable's value. Names use letters, digits and _, and start with a letter or _.

  • Local variables belong to one script. Set them in that script's Local variables box.
  • Global variables are one list shared by every script. The Global variables box shows the same list in every script; changing it there changes it for all scripts.
  • If a script has a local variable with the same name as a global one, the local value wins.
  • Write one variable per line as name=value. Blank lines and lines starting with # are ignored. Everything after the first = is the value (spaces at both ends are trimmed).
  • The value is inserted as plain text, exactly as written. Add quotes in the script if a value may contain spaces: cd "{{app_dir}}".
  • A {{name}} with no value is left as is and you get a warning. The editor shows which variables a script uses and which are missing.
  • Template syntax such as Docker's {{.Names}} or {{json .Config}} is not a variable and is never changed.
  • When you copy a library script into a Deployment, its variables are filled in at that moment.

Example. Global: env=staging. Local: service=nginx and lines=50. Script:

#!/bin/bash
echo "[{{env}}] restarting {{service}}"
sudo systemctl restart {{service}}
journalctl -u {{service}} -n {{lines}} --no-pager

Tags and filtering

  • Give scripts comma-separated tags. Click tags above the list to filter.
  • With two or more tags selected, choose how they combine: Any selected tag (OR) shows scripts that have at least one of them; All selected tags (AND) shows only scripts that have every one. The choice is remembered.

Broadcast

Type the same thing into many terminals at once. Open Broadcast on the Home page.

  • ＋ Add server… opens a terminal to a saved server. ＋ localhost opens a terminal on this computer; add as many as you like, for example to ssh to machines that are not saved.
  • Every key you type in a checked terminal (including Ctrl keys, arrows and paste) goes to all checked terminals. Checked terminals have a green border.
  • Uncheck a terminal to type into it alone, for example to answer a password prompt on one server. Turn off Broadcast Active to type into each terminal separately.
  • { } Scripts runs a script on every checked terminal, with its variables filled in.
  • Each terminal has its own connection; closing it (×) disconnects only that one.
  • A terminal whose connection failed or dropped, or whose shell ended, gets a red border. Click its ⟳ to reconnect it in place (the checkbox and position stay). ⟳ Reconnect all (n) at the top reconnects every failed or not-yet-connected Broadcast terminal at once; it only touches Broadcast, not server tabs.
  • Order the terminals by dragging a terminal's title bar onto another position (works in normal and Minimized view), or use the ⇅ Sort by… menu (Groups, Availability, Name, IP; localhost last). Groups follows the Home page order. The title bar takes its group's color.
  • The dot before each terminal's name shows the server's availability (green = up, red = not answering, grey = not checked).
  • The Shrink view button (9 small squares) shrinks every terminal and its text so many fit on screen. Double-click a terminal to enlarge it for typing (the rest stay small); double-click it again, or another one, to switch. Click Normal view (4 squares) to return all to normal.
  • Keep after restart reopens the same Broadcast terminals (and their checkboxes) next time the app starts. They are not connected automatically: click ⟳ Reconnect all to connect them.

Logs

  • Add as many log sources per server as you need, for example /var/log/syslog.
  • Live turns tailing on and off. Choose how many lines to load (200–5000).
  • INFO, WARN, and ERROR lines are colored. Filter by level or by time ("newer than").
  • Search can highlight matches or show only matching lines. Clear empties the screen without changing the file, and Download saves the full log file.

Metrics & alerts

  • Shows CPU, memory, and disk usage, plus top processes sorted by CPU or memory.
  • Set an alert limit on any gauge, and EranTerm notifies you when the server goes over it.
  • Maintenance actions: Clear cache / buffers, Clean disk (temp files and old logs), and ending a process. These need root, so the user needs passwordless sudo or a saved password.

Deployments

A deployment runs the same steps on many servers, one at a time or in parallel. You build it as a flow:

  1. Target servers come first (see below).
  2. Then add steps in the order they should run, with ＋ Command / script, ＋ Verification and ＋ Files. ⧉ Repeat last step adds a copy of the last one. Each step can be moved up or down, duplicated or removed.
  • Command / script: a command or a multi-line script (#!/bin/bash supported), typed or taken from the script library. A non-zero exit code fails that server.
  • Verification: a log check (a pattern is present or absent), a TCP port check, or a script exit code check, with an optional wait time. Choose whether a failure stops the deployment or only raises an alert.
  • Files: files and folders copied to every target server. Folders keep their structure.

The strip at the top of the builder draws the whole flow: servers → each step → Done. Empty steps are shown dashed and are skipped when the deployment runs. Click a step in the strip to jump to it.

While it runs, each server shows every step of the flow with its status. You can follow it live and reopen the last run's results afterwards. Deployments saved by older versions (Pre-deploy / Files / Deploy / Post-deploy) open as steps in that same order.

  • Target servers: narrow the list by group or by typing (name, host, tag or details), then use Select shown / Clear shown. Filtering never changes servers you've already selected.
  • ■ Stop ends the run right away: commands still running on the servers are stopped (with their child processes), and servers not started yet are skipped.
  • You get a desktop notification when a deployment finishes.

AI assistant

  • In the Terminal, describe what you want, and the AI suggests a command. Nothing runs until you approve it.
  • Ask AI in Terminal or Logs analyzes what's on screen, or the log lines that are currently shown.
  • Set it up in Settings → AI: choose a provider (Anthropic, OpenAI, Gemini or Cursor), paste an API key, and pick a model (Load models asks the provider for its current list). Test checks the key without saving it.
  • Cursor runs the Cursor CLI on this computer (cursor-agent; install with curl https://cursor.com/install -fsS | bash). The API key is optional: without one it uses your cursor-agent login. Model auto lets Cursor choose.
  • Text is sent to the provider only when you click Ask AI or request a command.

Settings & updates

Settings is split into tabs.

General

  • Theme: System, Light, or Dark.
  • Server connection default module: the module a server opens on when you connect: File Manager (default), Terminal, Logs or Metrics.
  • Reopen the open server tabs when the app starts: the tabs open when you quit (in their order, including localhost) reconnect at the next start. Off by default.

Server Availability

  • Turn background checks on or off for all servers, and set how often they run (seconds, default 60), on one line.

Updates

  • Update automatically: EranTerm checks for a new release at startup and every 6 hours.
    • Windows: the update downloads in the background. Restart when you're asked, or it installs the next time you quit.
    • macOS: you're offered the download page. Open the new .dmg and drag EranTerm into Applications.

Logging

  • Optionally save the app log to eranterm.log in a folder you choose (default: ~/Library/Logs/EranTerm on macOS).
  • Log Console: open it with the ›_ Log Console button in the side menu, from Settings, or with Ctrl/⌘ + Shift + L. It has two tabs:
    • ▤ Log: a live view of the app log, with a filter and a level picker. Debug level also logs every internal call and extra detail; it is off by default and turns off again when the app restarts.
    • ★ Action Log: the audit trail. Every server, user, group, script and deployment you create, change or delete; settings changes; connections and remote desktops; file uploads, downloads, deletes and new folders; killed processes; maintenance actions; and deployment runs. Each row has the time, the action, the target, details and whether it worked (failed actions show the error in red). Filter by text or action type, show failed actions only, or Copy CSV. The Action Log is saved in actions.jsonl in the data folder and kept across restarts. Passwords, keys and file contents are never recorded.

AI

  • Provider, API key and model: see AI assistant.

Notifications

  • Desktop (OS) notifications for: a server going down or coming back up, a deployment finishing, and metric alerts. On by default.
  • Help → Version shows your version. Help → Check for Updates… checks right away. Help → User Manual (F1) opens this page.

Google account & backup

Sign in with your own Google account (Gmail or a company account) in Settings → Account. Signing in is optional; without it EranTerm works as before, all on this computer.

  • Backup to your Google Drive: once signed in, your servers, saved users, groups, scripts, global variables, deployments, environments and settings are saved to your own Google Drive a few seconds after each change. They go to a hidden app folder: only EranTerm can see it, and it does not appear among your Drive files.
  • Other computers: sign in with the same Google account and everything comes back. If both computers changed things, EranTerm asks which copy to keep.
  • Never backed up: passwords, SSH keys and AI API keys. Enter them once on each computer. Logs, the Action Log and host keys also stay local.
  • Backup now (Settings → Account) uploads this computer's configuration right away; Restore from backup replaces this computer's configuration with the saved copy. Automatic backup can run on every change and/or daily or weekly. EranTerm also checks at startup. Sign out keeps everything on this computer.
  • To remove the backup: Google Drive → ⚙ Settings → Manage apps → EranTerm → Delete hidden app data.

One-time setup: Google sign-in

For whoever builds EranTerm for the team, once. Google requires any app with "Sign in with Google" to be registered as an OAuth client. The registration holds no user data: each user's backup lives in their own Drive. Any Google account can own it. Until it's done, Settings → Account says sign-in is not set up.

  1. Go to console.cloud.google.com and create a project (e.g. EranTerm).
  2. APIs & Services → Library: search for Google Drive API and click Enable.
  3. Open Google Auth Platform (the OAuth consent screen):
    • Branding: app name EranTerm and your email.
    • Audience: External, then Publish app (so it is "In production"; in "Testing" sign-ins expire every 7 days).
    • Data access: add openid, email and .../auth/drive.appdata (the app's own hidden Drive folder only).
  4. Clients → Create client → Desktop app, name EranTerm desktop. Put the Client ID and Client secret in CONFIG at the top of cloud.js, then build. They are not secrets: desktop apps ship them by design.
  5. In EranTerm: Settings → Account → Sign in with Google. If Google shows "Google hasn't verified this app", click Advanced → Go to EranTerm.

Security & data

  • Passwords and API keys are encrypted with your OS keychain and never leave your machine, except when they're used to log in or to call the AI provider.
  • Everything is stored locally. If you sign in with Google, a copy of your configuration (without passwords or keys) is kept in your own Google Drive (see Google account & backup).
  • Host keys are pinned after the first connection.
